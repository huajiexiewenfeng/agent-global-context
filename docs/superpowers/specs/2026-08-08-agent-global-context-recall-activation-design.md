# Agent Global Context：最小 Recall 激活设计

> 状态：已确认，待实施  
> 日期：2026-08-08  
> 范围：只优化 Recall 激活与应用，不修改 Runtime、Capture、Trace 或 Eval

## 1. 目标

本阶段只解决一个问题：AGC 已经能够可靠保存记忆，但 Codex 在多数适用任务中没有想起调用它。

目标可以概括为：

> 存得对、想得起、用得值；不相关时保持安静。

成功不是提高所有任务的 Recall 调用率，而是让个人背景可能实质改变结果的任务更容易调用 AGC，并在读取后只应用真正有价值的记忆。

## 2. 当前证据

2026-08-01 至 2026-08-08 的本机审计显示：

- AGC 有 22 条正式记忆，校验通过，Catalog 能在正式写入后自动刷新。
- 73 个真实 Codex 执行任务中只有 2 个调用过 AGC。
- 尚未观察到已有记忆在后续独立任务中被明确用于 `adapt`、`continue` 或 `grow`。
- 当前薄 Skill 的描述只写了“任务可能受益时使用”，触发范围过于抽象。

因此，本阶段不改存储模型。首要断点是 Skill 激活，而不是记忆数量、Schema 或搜索能力。

## 3. 非目标

本阶段不做：

- 新的 Runtime action 或搜索协议。
- 向量检索、语义排序或自动 Prompt 注入。
- Codex 完成后的旁路 Capture。
- Trace、Eval 或自动进化闭环。
- 全量历史任务回填。
- 为未来数百条记忆提前设计复杂分层。

## 4. 最小方案

### 4.1 强化始终可见的触发描述

修改 `agent-global-context` 的 Skill description，使模型在以下场景更容易选中它：

- 重要方案、权衡和决策。
- 个性化写作、沟通和协作。
- 学习、研究或成长规划与复盘。
- 跨任务继续既有目标、决定或工作。
- 用户明确提到自己的背景、习惯、原则、偏好或目标。

描述中同时写明排除项：简单、自包含、事实性或机械性任务不使用 AGC。

始终可见的描述不包含任何个人事实，目标保持在约 50–80 Token。

### 4.2 使用一个简单的价值判断

LLM 在决定是否读取前只判断：

> 如果不知道用户的长期背景，这次任务的决策、表达、连续性或成长价值是否可能明显变差？

- 否：不调用 `agc.read`。
- 是：调用现有读取接口。

任务复杂并不自动意味着需要 Recall。若代码、日志、实时数据或当前对话已经提供完整依据，仍然不调用 AGC。

### 4.3 复用现有渐进读取

不修改 Runtime。普通 Recall 使用现有链路：

```text
overview → search → 必要时 get → 极少数情况 history/evidence
```

约束如下：

- `overview` 只确认可用的 kind、scope 和紧凑卡片。
- `search` 优先使用 `scope`、`kind`、`decision_impact` 等现有 filters，并把 `limit` 控制在 5 以内。
- 当前 Runtime 的 `query` 是字面子串匹配，因此普通 Recall 不生成长自然语言查询；不确定时只用 filters。
- 只有紧凑卡片不足以判断适用边界时才调用 `get`。
- 只有冲突、变化或来源核验才调用 `history` 或 `evidence`。
- 读取失败时放行主任务。

为避免普通 Recall 加载完整写入 Schema，`SKILL.md` 内直接提供上述最小读取说明。完整 `tool-contract.md` 只在写入、管理或需要精确完整 Schema 时读取。

### 4.4 读取不等于应用

读取后，只有记忆能够实质改善以下至少一项时才应用：

- 决策选择。
- 表达或协作方式。
- 跨任务连续性。
- 与用户明确目标相关的成长支持。

应用时仍选择一种现有模式：

- `adapt`：静默调整表达、深度或协作方式。
- `continue`：核对当前状态后延续既有目标或决定。
- `grow`：只在存在明确 active goal 时给出至多一条强相关建议。

如果读取结果无关、过时、证据不足或不会改变结果，就直接丢弃；不为了展示记忆能力而向用户复述记忆。

## 5. 实施范围

第一阶段只修改：

1. `skills/agent-global-context/SKILL.md`：增强 description、触发规则、排除规则和最小读取说明。
2. `tests/test_skill_adapter.py`：验证高价值触发场景、低价值排除场景、最小读取链路和价值门槛仍然存在。

除非测试证明现有读取接口无法支持该设计，否则不修改 `agc_runtime/`。

## 6. 验证方式

### 6.1 发布前

- 现有 Runtime 与 Skill 测试全部通过。
- `agc.admin validate` 继续通过，正式记忆数量和内容不发生变化。
- 用一组正反例检查 Skill 路由：重要决策、个性化写作、学习研究、成长复盘、跨任务延续应命中；简单事实、机械编辑和纯证据诊断应跳过。

### 6.2 发布后

先观察后续 10 个“个人记忆可能实质改变结果”的真实任务，不引入新的 Trace/Eval Runtime。复查时只回答三个问题：

1. 该调用时是否调用了 AGC？
2. 调用后是否有记忆真正改变了决策、表达、连续性或成长支持？
3. 是否在无关任务中制造了调用和噪声？

若激活仍然不足，再考虑宿主侧能力提示；若激活充分但经常找不到相关记忆，再单独优化 Search。当前阶段不提前解决这两个尚未被证实的问题。

## 7. 预期结果

本改动不会让每个任务都读取记忆，也不保证 Recall 达到 100%。它应当带来更实际的结果：

- 高价值任务更容易想起 AGC。
- 无关任务仍可保持零个人记忆 Token。
- Recall 调用以产生实际应用为目的，而不是只证明记忆存在。
- 存储层继续保持稳定，改动失败也不会影响主任务和已有记忆。
